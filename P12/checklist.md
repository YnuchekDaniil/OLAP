# Чеклист готовности проекта к зачёту

## 1. Стенд и окружение
- [x] **Стенд воспроизводим:** ClickHouse и Metabase поднимаются из корня командой `docker compose up -d` на любой машине, а не «только дома».
- [x] **Порты и сервисы:** ClickHouse HTTP (`8123`) отвечает `Ok.` на `curl http://localhost:8123/ping`, Metabase доступен на порту `3000`.
- [x] **Сырые данные на месте:** Все 9 исходных CSV-файлов лежат в репозитории по пути `P01/data/raw/`, а не на внешних дисках или флешке.

## 2. Модель данных и витрина
- [x] **Фиксация Grain:** Есть чёткая фраза: *«Одна строка факта = одна позиция товара в заказе (`order_id + order_item_id`)»*.
- [x] **Точность денег:** Все финансовые поля (`price`, `freight_value`, `revenue`) строго хранятся в типе `Decimal(12, 2)` (не во `Float`/`Double`).
- [x] **Схема «звезда»:** В центре факт `fact_order_items` (`112 650` строк), вокруг 4 измерения (`dim_product`, `dim_customer`, `dim_seller`, `dim_date`).
- [x] **Идемпотентность загрузки:** Скрипты загрузки перед вставкой выполняют очистку (`TRUNCATE` / `DROP`), повторный запуск не удваивает факт и не раздувает суммы.

## 3. Аналитический SQL и качество (DuckDB & ClickHouse)
- [x] **Качество данных (ELT):** Проверки на `NULL`-ключи, неотрицательные цены и отсутствие «сирот» встроены в скрипты загрузки и прерывают процесс при ошибке.
- [x] **Аналитические запросы:** На все 3 вопроса из паспорта написан рабочий SQL (`P04/sql/analytics.sql`, `P08/sql/analytics_ch.sql`).
- [x] **Оконные функции:** Присутствуют запросы с оконными агрегатами (`RANK() OVER (...)` для рейтингов категорий/продавцов и `SUM(...) OVER (...)` для долей в обороте).
- [x] **Каноническая метрика:** Главная мера `revenue` вынесена в отдельный скрипт `canonical_metric.sql` и совпадает с текстом в паспорте.

## 4. История справочников (SCD)
- [x] **Реализация SCD2:** Механизм версионирования с атрибутами `valid_from`, `valid_to`, `is_current` и суррогатным ключом `product_sk` реализован и доказан в `P06` (`dim_product_scd2`).
- [x] **Фиксация отказа в проде:** Использование SCD1 в боевой витрине ClickHouse честно зафиксировано и аргументировано в `cut.md`.

## 5. ClickHouse и физическое хранение
- [x] **Движок MergeTree:** Таблицы ClickHouse созданы на движке `MergeTree`.
- [x] **Осознанный `ORDER BY`:** Порядок полей `(order_status, date_key, product_id, seller_id, order_id, order_item_id)` обоснован структурой частых фильтров запросов (статус и дата стоят первыми).
- [x] **Нет ложных утверждений:** В документации прямо указано, что `ORDER BY` в ClickHouse — это разреженный индекс и сортировка, а не уникальный первичный ключ (PK) как в OLTP.
- [x] **Партиции:** Обоснованный отказ от нарезки факт-таблицы на партиции (`tuple()`) оформлен в `P08/cut.md` и корневом `cut.md` (размер таблицы всего ~11 МБ).

## 6. Сводная таблица (Aggregates)
- [x] **Сводка под график:** Создана сводная таблица `olist_dw.agg_daily_category_sales` под графики динамики и категорий дашборда.
- [x] **Grain сводки:** Чётко разделены понятия: одна строка сводки = *день + категория товара*.
- [x] **Сверка сумм:** Суммы сводки полностью сходятся с детальным фактом (`diff = 0.00` в `P09/summary_check.txt`).
- [x] **Регламент пересчёта:** Описан и автоматизирован пересчёт сводки (`python P09/scripts/build_summary.py`) после повторной заливки факта.

## 7. BI и визуализация (Metabase)
- [x] **Прямой источник:** Metabase подключён напрямую к серверному ClickHouse (`olist_dw`), а не к локальному файлу DuckDB.
- [x] **Драйвер ClickHouse:** Установлен и подключён официальный драйвер `clickhouse.metabase-driver.jar` (v1.52.0).
- [x] **Дашборд:** Собран дашборд из 5 виджетов (карточка KPI, динамика по месяцам, топ категорий, топ штатов, топ продавцов).
- [x] **Фильтрация:** На дашборде работает общий фильтр по датам (`Период`), привязанный через переменные `{{period}}` во всех запросах.
- [x] **SQL виджетов сохранён:** Все тексты SQL-запросов дашборда скопированы в репозиторий в папку `P10/dashboards/`.

## 8. Сверка SQL и BI (Главный критерий)
- [x] **Одно число:** Запрос `canonical_metric_ch.sql` в ClickHouse и карточка KPI на дашборде при одинаковых фильтрах показывают **одно и то же число**: `13,221,498.11` (расхождение `0.00`).
- [x] **Протокол сверки:** Составлен и сохранён подробный протокол с условиями проверки (`P11/reconciliation.md`).
