# P05. Загрузка и проверки (ELT)

## Структура

```text
OLAP/
├── P01/data/raw/                 # исходные CSV Olist
└── P05/
    ├── etl/
    │   ├── ddl_duckdb.sql        # DDL таблиц витрины
    │   └── run_elt.py            # ELT-пайплайн с проверками качества
    ├── run_log.txt               # лог двух прогонов подряд
    ├── olist_dw_p05.duckdb       # база DuckDB (создаётся скриптом)
    └── README.md
```

## Цепочка ELT
1. **Сырьё → `stg.*`**: загрузка CSV из `P01/data/raw/` в промежуточные таблицы схемы `stg`.
2. **Проверки качества (`stg.*`)**:
   - пустые ключи и суммы (`NULL`);
   - диапазон значений (`order_item_id >= 1`, `price > 0`, `freight_value >= 0`, даты в `2016–2026`, габариты и вес `>= 0`);
   - дубли по зерну `(order_id, order_item_id)` и ключам справочников;
   - «сироты» — ссылки из факта, отсутствующие в `dim_product`, `dim_customer`, `dim_seller`, `dim_date`.
   При провале любой проверки загрузка **останавливается** до обновления витрины.
3. **Справочники → факт**: сначала загружаются `dim_product`, `dim_customer`, `dim_seller`, `dim_date`, затем `fact_order_items`.

## Что чистим при повторном запуске
Перед загрузкой в боевую витрину полностью удаляются и пересоздаются целевые таблицы (`main.fact_order_items`, затем `main.dim_product`, `main.dim_customer`, `main.dim_seller`, `main.dim_date`), после чего справочники и факт заливаются заново в одной транзакции — поэтому повторный прогон не удваивает строки и суммы.

## Как запустить (два прогона подряд и тест остановки)

```bash
# Два прогона подряд с записью чистого UTF-8 лога в P05/run_log.txt
python P05/etl/run_elt.py --log P05/run_log.txt
python P05/etl/run_elt.py --log P05/run_log.txt --append

# Проверка, что плохие данные останавливают загрузку (должен вернуть ошибку и не менять витрину)
python P05/etl/run_elt.py --simulate-bad-data
```
